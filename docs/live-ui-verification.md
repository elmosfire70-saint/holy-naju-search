# 실시간 검색 A 화면과 운영 전환 검증

2026-11-06. 자체 검색/목록 보완·원문 검증·결과 보관 CLI를 A 화면/API에 연결했다. 일반 한국어 검색 품질이나1차 출시 전체를 완료했다는 뜻은 아니다.

## 구현

- 기본 방식은 교황청 실시간 검색. 기존 보관 검색·나주·파일·원문/로컬 번역 reader는 유지했다.
- POST `/api/live/search`는 query만 받고 작업 ID를 즉시 반환한다. GET `/api/live/jobs/{id}`로 단계를 조회하고 완료 후 `/api/live/runs/{id}`로 저장 결과를 연다.
- 서버당 백그라운드 작업1개, 최근20개 작업 상태만 메모리에 보존한다. 실행 이력은 DB에 저장한다. 해당 서버에서 실시간 검색과 제한 수집은 동시에 실행하지 않는다. 별도 CLI/여러 서버의 전역 동시성 조정은 아직 없다.
- `/api/live/history`는 최근100개 실행을 반환한다. 당시 열기와 새 온라인 재검색을 구별한다. 실패는0건으로 표시하지 않는다.
- 문헌별 결과/확인 시각/발견 경로·원문 블록별 선택·문자 위치 강조를 제공한다. 번호로 시작하는 본문을 먼저 표시하지만 이를 공식 번호 추출로 표현하지 않는다. 목차/각주도 선택 가능하다.
- 기존 performSearch 끝의 범위 밖 scroll 참조를 제거하고 결과 렌더 함수 안에서 스크롤을 복원했다.

1. 운영8766포트 미사용, 수집/가져오기 실행0 확인. 임의 서비스나 사용자 프로세스를 종료하지 않았다.
2. `data/backups/before-live-ui-20261106-h4widwex`에 SQLite backup API로 DB를 복제하고 assets668개를 복사했다. 복사 DB quick_check/FK와 전체 자산 SHA256이 정상이다.26개 기존 테이블의 정렬된 행/내용 해시를 manifest로 보존했다.
3. 운영 DB를 스키마5로 전환하고 기존26개 테이블을 행 수/내용 해시로 대조해 동일함을 확인했다. 새 서버를 숨김 실행하고8766 원래 주소에서 기본 모드/668판 표시를 확인했다.
4. 운영 화면에서 공동 구속자로 새 실행 `f765c80d-f4e1-44aa-bf71-8c2a083ca5da`를 만들었다. 목표 원문을 포함한2문헌/27일치구간이 저장돼670판이 됐다. 기존26개 테이블의 옛 모든 행이 그대로 포함되고 FK 오류0/running0이다. 기존 번역/파일/기록을 지우지 않았다.
5. 시험8768 서버는 경로/명령줄을 확인한 뒤 종료했다. 운영8766은 유지한다. 바탕화면 실행 바로가기는 기존 서버를 재사용한다.

백업은 검사했지만 완전한 복원 훈련/전원 장애 복구를 검증한 것은 아니다. rollback이 필요하면 현재 새 자료도 보존하고 이전 코드와 스키마4 백업을 별도 경로에서 열어야 한다. 새 DB 위에 백업을 덮어쓰지 않는다.

## 남은 한계

- 영어 자체 검색 첫 페이지·신앙교리부 영어 목록·본문최대5개만 확인한다. 공동 구속자 관련 명시적 용어 대응 외 일반 한국어 질의 자동 번역은 아직 없다. 다른 질의는 원문 제목/용어가 필요하다.
- 제목/용어 일치와 인간 관련성 승인은 다르다. 전체 Recall/nDCG·번역 품질 출시 판정은 미완료다. 새 모델 번역 생성은 이번 UI 검증에서 실행하지 않았다.
- 화면 이동/새로고침은 작업 취소가 아니다. 재접속 후 진행 중 작업 ID 자동 복원/취소, 서버 재시작 시 running→interrupted 자동 복구, 다중 프로세스/CLI의 통합 잠금, 저장 실패 자산 정리 및 복원 훈련은 후속 작업이다.
