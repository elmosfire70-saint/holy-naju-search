# 확대 자료의 검색·번역 평가

2026-10-31, 이슈 #12. 50문항은 에이전트 작성 초안이며 인간이 승인한 연구 질문·정답 세트가 아니다. 이 도구는 검토 준비와 재현 가능한 비교를 제공하며 1차 출시를 자동 승인하지 않는다.

아래 최초 실행의 긴 문단 오류는 후속 #13에서 수정했다. [긴 문단 수정 검증](long-passage-verification.md)의 재평가는 키워드50개/결합42개 정상·대체0개다. 최초 실행 결과는 실패 이력으로 그대로 남긴다. 인간 관련성/번역 판정은 여전히 미완료다.

## 범위와 실행

`config/quality-evaluation.json`은 나주18·공의회12·교리서10·회칙4·가져온 파일2·전체/단문/무결과 점검4개 질문을 포함한다. 한국어 주제·짧은 질의, 영어/이탈리아어 자료 필터, 외국어 제목/구절과 OCR 시험 파일을 구분한다. 무결과 점검 질문도 전체 자료에 관련 근거가 없다는 인간 판정은 아직 없다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py
# 모델 없이 키워드/구절 후보만 준비한다.
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py --keyword-only
```

실행마다 `data/evaluation/quality-시각-고유값/`을 새로 만든다. SQLite backup API와 원본 파일 복사로 `library/`에 분리된 보관소를 만들고 무결성을 점검한다. 원래 연구 보관소를 읽기 전용으로 열며 검색·번역·임베딩/기록을 변경하지 않는다. 전체 원본 복사 공간과 첫 임베딩 생성 시간이 필요하다. 평가 보관소의 모델 캐시는 연구 보관소로 자동 승격하지 않는다.

기존 `search` 경로를 그대로 사용한다. 상한20, 키워드/구절과 로컬 `qwen3-embedding:0.6b` 결합 검색을 비교하고 실제 검색 실행 ID·당시 근거 snapshot·색인 세대·모델 digest·진단·소요 시간·재사용을 저장한다. 구절8문항은 결합 검색 미지원이므로 키워드/구절 경로만 실행한다. 첫 모델 실패/키워드 대체가 나타나면 같은 실행의 나머지 모델 요청은 멈추고 키워드 평가는 계속한다. 대체를 결합 검색 성공으로 집계하지 않는다.

새 의존성·DB 스키마·모델·외부 API·수집·검토 UI는 추가하지 않았다. 기존6문항 URL 적중 도구는 과거 소규모 비교 재현용으로 그대로 유지한다.

## 사람이 검토하는 파일

모든 개인 원문/결과/판정은 위 폴더의 `report/`에만 두며 Git에 올리지 않는다.

- `results.json`은 각 요청의 실제 순위·실행 상태·지표/미계산 사유다. 지표가없다는 것과0점은 다르다.
- `review.md`는 질문·출처/언어/문헌 종류 조건·근거 수·로컬 앱의 원문 링크다. 기본127.0.0.1:8766에서 같은 연구 보관소를 실행해야 한다. 다른 보관소의 ID는 해당 보관소 서버에서 열어야 한다.
- `review.json`은 검색 후보 풀과 관련성 판정 입력이다. 원문 전체·URL·출처·언어·위치·문단/버전 ID·텍스트 해시를 보존한다. 기본은 `status=pending`, `grade=null`이다.
- `translation-review.json`은 기존 번역의 원문/출력·실패/미검토·모델/프롬프트와 충실성·주어/부정·가톨릭 용어·숫자/참조·누락/추가를 점검할 수 있는 별도 작업지다. 새 번역을 생성하거나 판정을 연구 DB에 반영하지 않는다. 이 작업지의 점수를 자동 집계하는 기능도 아직 없다.

질문이 실제 연구 목적과 맞는지 먼저 확인한다. 질문을 수정하면 원래 판정을 재사용하지 말고 새 데이터셋으로 다시 후보를 생성한다. 각 문항의 후보를 원문과 대조해0=무관,1=보조 관련,2=질문에 직접 답하는 근거를 `judgments[].grade`에 기록한다. 원문·해시·질문 조건은 수정하지 않는다. 검토자가 후보 풀 밖의 관련 근거를 발견하면 해당 문단 ID·버전·원문·해시를 추가해 정답 후보 풀을 보완한다. 사람이 검토하지 않은 후보를 자동으로0점 처리하지 않는다.

한 문항의 관련성 검토를 마친 뒤 해당 문항에 아래처럼 기록한다. 예시는 형식 설명일 뿐 실제 승인 기록이 아니다.

```json
{"status":"reviewed","reviewed_by":"실제 검토자 이름","reviewed_at":"2026-10-31T20:00:00+09:00"}
```

수정한 `review.json`을 입력해 재평가한다. 모델 캐시를 재사용하려면 첫 평가의 `library`를 원본으로 지정할 수 있다. 이때도 새 복제본에 실행하며 기존 판정 파일을 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py --root 'data/evaluation/quality-실제실행폴더/library' --review 'data/evaluation/quality-실제실행폴더/report/review.json'
```

재실행의 새 `review.json`은 이전 등급을 보존하되 검토 상태를 다시pending으로 둔다. 새 후보가 있으면 함께 검토해야 하며 이전 입력 파일과 검토자 이력은 그대로 유지된다. 지표는 명령에 입력한 판정 파일 기준이다.

## 지표의 의미와 방어

코퍼스는 현재 버전 ID/본문 해시·제목/출처/언어/문헌 종류/날짜의 지문으로 고정한다. 질문 전체·순서·조건도 해시로 묶고 검토 파일의 질문/조건·문단 ID/버전·원문/해시를 대조한다. 원문이나 질문이 바뀐 판정, 중복 근거,0/1/2가 아닌 등급, 빈 검토자와 시간대 없는 검토 시각은 거부한다.

`reviewed`인 문항에만 알려진 관련 문단(등급1/2) 기준의 `pooled_recall_at_20`과 이득 `2^grade-1`, 할인 `log2(rank+1)`을 사용한 `pooled_ndcg_at_10`, 관련 문단 상위20 적중 여부를 계산한다. 새 순위에 미판정 문단이 있으면 `unjudged_results`로 제외한다. 관련 근거가0개인 문항은 지표를null로 두며 완벽한 재현율/순위 점수로 취급하지 않는다. 이 경우 반환 수·빈 결과를 별도로 검토해야 한다.

이는 **검토한 후보 풀 기준**의 지표다. 모든 문단의 관련성을 빠짐없이 판정한 전역 Recall이나 신학적 정답률이 아니다. 두 방법 모두 점수가 있는 같은 문항의 수·평균을 별도로 기록해 서로 다른 표본의 평균을 우열 비교하지 않게 한다. 합격 임계값은 아직 사용자와 확정하지 않았고 `release_passed`는false로 유지한다.

## 검증과 남은 일

합성 테스트에서 알려진 등급의 수식·빈 분모·잘못된/불리언 등급·중복 순위·미검토/새 근거·질문/코퍼스/원문 변경·검토자/시각·모델 대체와 반복 호출 중단을 검사한다. 이 테스트의 합성 검토자/정답은 실제 연구 자료의 인간 승인으로 사용하지 않는다.

실제50문항 실행 결과와 보관소 보존 검사를 아래에 기록한다. 인간 검토50문항과 번역 개선·출시 판정은 여전히 남아 있다. 특히 과거 이탈리아어 번역 오류가 이 작업으로 해결된 것은 아니다. 학습형 재정렬기·ANN·2차 종합 답변은 추가하지 않았다.

## 실제 실행 결과

668개 문헌판·15,375개 문단의 복제본에서 최초 실행은18:52:12~19:00:06 KST였다. 최종 코드로 저장된 캐시를 다시 복제해19:01에 재실행했다. 질문/코퍼스 지문과 완료된 키워드50개·결합35개의 검색 실행 ID가 모두 같았다.

| 요청 방식 | 정상 실행 | 키워드 대체 | 미실행 | 인간 검토 점수 |
|---|---:|---:|---:|---|
| 키워드/구절 | 50 | 0 | 0 | 미계산 |
| 로컬 결합 | 35 | 1 | 14 | 미계산 |

결합 미실행14개는 구절8개와 첫 오류 이후 중단한 주제6개다. 이 숫자는 실행 상태이며 정답 적중률/검색 정확도가 아니다. 관련성 판정은50문항 모두pending이고832개 문항별 근거 후보(고유 문단730개)는 모두grade=null이다. 후보가없는 질문도 있으며 이를 정답 부재/재현율1로 간주하지 않았다. 지표 대상 문항0개, 두 방법 공동 판정0개, 평균null, release_passed=false다.

기존 번역5개(생성 완료4·실패1)의 원문·출력/오류·미검토·모델/프롬프트를 검토 작업지에 내보냈다. 새 번역을 생성하거나 오역을 개선했다고 주장하지 않는다.

### 발견한 실제 실패

E01의 회칙 필터에서 `local_model_unavailable:HTTPError`가 발생했다. 실제 실패 배치와 가장 긴 문단의 단독 요청을 확인한 결과, 두 경우 모두 로컬 Ollama가 HTTP400 `the input length exceeds the context length`를 반환했다. 입력은 Redemptoris Mater의 한 문단/제목17,298자, num_ctx4096, truncate=false였다. 에러명만 보고 네트워크 장애로 추측하지 않았다.

문단 ID는 `d1eb3449-bef1-4479-8193-b2f33218651c`, 원문 버전은 `436c79b4-eb33-4f70-83fb-0d8f545941aa`다. 원문을 자르거나 제외해 오류를 숨기지 않았으며, 긴 문단 처리/근거·캐시 보존과 재평가를 후속 이슈 #13으로 분리했다. 따라서 확대 코퍼스의 결합 검색 전체가 정상이라고 보고하지 않는다.

### 로컬 증거와 재검증

최초 결과는 `data/evaluation/quality-2026-10-31T09-52-07.488720+00-00-7146ca90/`, 최종 검토 자료는 `data/evaluation/quality-2026-10-31T10-01-12.932112+00-00-6d06924d/report/`에 있다. 직접 오류 진단은 최초 폴더의 `embedding-error.json`에 보관했다. 파일과 원문은 개인 데이터이며 Git에 포함하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_evaluation.py -v
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py --root 'data/evaluation/quality-2026-10-31T09-52-07.488720+00-00-7146ca90/library'
```

평가 전용7개·전체60개 테스트 통과, 생략없음. 실제 두 평가 명령은 종료코드0이지만 이는 보고 생성 성공이지 결합 검색/정확도 전체 통과가 아니다. 원래 연구 DB의 실행 전·후 SHA256은 `719d483df75b439aeafea80f56336bbc74a2c573b98179245e2d00bb4799e0d2`로 같았다. 사용자 원문·모델/번역·검색/기록 행을 포함한 DB 바이트를 바꾸지 않았다.
