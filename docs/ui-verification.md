# A 연구실형 실제 UI 검증

2026-10-31. 사용자가 A 연구실형을 선택해 이슈 #8을 종료하고 #9에서 실제 로컬 UI를 구현했다. 원본 3안은 `prototype/ui-layout-review/c5efb3a`에 남긴다. main에는 시안·가상 검색 상태·배치 전환 바를 가져오지 않았다.

## 구현한 범위

- 왼쪽 메뉴·검색 조건·결과 목록·원문/한국어 번역 병렬 화면.
- 기존 `Library`, 검색/필터/캐시/기록, 로컬 문단 번역 함수를 호출하는 HTTP API.
- 자료실 파일 선택·언어/제목·가져오기, 문헌 버전·문단 열기, 원본 파일 다운로드.
- 저장 번역 선택과 모델/프롬프트·미검토 상태, 명시적 번역 생성·재사용.
- 당시 검색 열기와 현재 보관 자료 재검색. 특정 run/passage/translation ID의 주소 복원.
- 근거 원문·버전·문단·선택 번역 ID 복사. 검색 당시 제목/출처를 우선 표시한다.

새 프레임워크나 런타임 의존성을 설치하지 않았다. Python 표준 HTTP 서버는 개인 PC 루프백 전용이며, 브라우저는 HTML/CSS/JavaScript를 사용한다. SQLite 스키마는 버전 3을 그대로 사용한다.

## 경계와 실패 처리

- 서버는 `127.0.0.1`로만 실행하고 Host와 상태 변경 요청의 Origin·전용 헤더·Content-Type을 확인한다. CORS를 허용하지 않는다.
- 정적 파일은 명시한 화면 파일만 제공한다. 임의 경로·DB 파일 요청은 거부한다.
- 가져오기는 선택 파일의 바이트만 전달한다. 파일명 경로/Windows 예약 이름·확장자·언어·50MiB 상한을 검사한다. 원래 PC 경로는 브라우저가 제공하지 않으므로 임시 폴더 경로가 유입 이력에 남는다. 원본 이름과 보관 해시/파일 연결은 유지한다.
- 원본 HTML/가져온 텍스트는 실행하지 않고 이스케이프한 텍스트로 표시한다. 원본 파일은 hash를 확인한 뒤 attachment로 내려준다.
- 정상 빈 결과와 검색 실패를 구분한다. 실패 후 남은 문단이 있다면 직전 결과라고 표시한다. 의미 검색 대체와 번역 실패를 명시하며 원문을 지우지 않는다.
- HTTP 요청별 SQLite 연결을 사용한다. 화면/문단/번역 요청의 늦은 응답이 다른 선택을 덮어쓰지 않도록 구분한다.

이 경계는 로컬 개인 앱용이다. 인증·TLS·공용 배포·멀티 사용자·네트워크 공격 부하에 대한 검증이 아니며, 서버를 외부에 노출하지 않는다.

## 실제 브라우저 검증

Chrome 1600×1000 및 390×844에서 확인했다.

| 검증 | 결과와 범위 |
|---|---|
| 한국어→외국어 | 실제 교황청 보관 자료에서 성경/성전 질문으로 Dei Verbum 근거 표시 |
| 검색 재사용 | 동일 조건의 저장 결과 재사용 안내와 같은 실행 확인 |
| 원문/번역 | 영어 원문과 저장 한국어 미검토 번역, 버전 정보 표시 |
| 번역 버튼 | 기존 정상 번역을 재사용하는 로컬 API 경로 확인 |
| 심층 링크 | 검색·문단·번역 ID를 포함한 주소 새로고침 후 같은 보관 근거 열기 |
| 기록 | 당시 열기는 모델 없이 결과 조회, 재검색은 새 실행 ID 생성 |
| 자료실 | 실제 문헌 목록→버전→문단→원문 표시 |
| 오류 표시 | 브라우저에 주입한 검색 503/번역 502를 정상 빈 결과와 구분, 원문 유지 |
| 좁은 화면 | 검색·자료실·기록에서 390px 가로 넘침 없음 |

가져오기 검증은 실제 연구 보관소와 분리한 `data/ui-integration/library`에서 했다. TXT 선택·중복 가져오기의 같은 버전 재사용, 스크립트 문자열 무실행, 합성 스캔 PDF의 로컬 한국어 OCR·페이지·미검토 표시를 통과했다. DOCX·HTML·혼합 PDF는 기존 추출 테스트의 범위이며 이번 브라우저 가져오기에서는 TXT와 스캔 PDF만 확인했다.

검증 중 발생한 favicon 404를 보완했다. 재검색 검사는 API 응답 전의 기존 ID를 읽는 테스트 대기 조건을 수정한 뒤 새 ID 생성을 확인했다. 실패 주입 때 생기는 HTTP 콘솔 오류는 의도한 테스트이며 실제 번역 품질 통과를 의미하지 않는다.

브라우저 검증 코드와 캡처는 Git 제외된 `data/ui-review/output/playwright/`에만 남긴다. 해당 PC에서 `playwright-cli -s=holy-ui-review run-code --filename output/playwright/app-check.js`와 `import-check.js`로 실행했다. 후자는 격리 보관소가 준비된 최초 상태를 전제로 한다.

최종 `app-final-check.js`는 지연된 번역 응답이 선택 해제를 덮지 않는지, 출처/언어/종류/상한 필터가 실제 요청에 연결되는지, 검색 기록에 포함되지 않은 문단 링크를 거부하는지와 저장 근거/번역 복원을 추가로 통과했다.

## 자동 테스트와 보관소

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node --check holy_naju/web/app.js
.\.venv\Scripts\python.exe -X utf8 scripts/import_documents.py check
git diff --check
```

기존 38개와 HTTP 7개, 총 45개가 통과했다. 생략은 없다. HTTP 테스트는 보안 헤더·Host/Origin·요청 형식/크기·경로/파일명 거부·검색/기록 재사용·원문/파일 연결·저장 번역의 모델 없는 조회·키워드 대체·오류 상태를 포함한다. 화면 이동으로 발생한 Windows ConnectionAbortedError에 두 번째 HTTP 오류를 보내지 않는 회귀 검사도 추가했다. 실제 보관소 검사는 `ok=true, problems=[]`였다.

연구 보관소는 문헌·언어판·파일·원문 버전 각 6개, 문단 468개를 그대로 유지했다. 브라우저 검증은 검색 기록과 정상 재검색 실행을 추가했으며 기존 문헌이나 원문을 덮어쓰지 않았다. 가져오기 시험 문서는 격리 보관소에만 있다.

## 아직 남은 범위

전체 사랑의 메시지와 시대별 공의회 문헌 수집·상태 목록, 인간 검토 50문항·번역 품질/Recall/nDCG, 실제 역사 스캔 OCR, 대규모 성능·중단 재개·백업 복구는 미완료다. PDF는 파일 다운로드와 근거 페이지 번호 연결까지이며 내부 페이지 뷰어는 후속 범위다. 기록 화면은 최근 100개 요청을 표시한다. 사용자 번역 교정/검토 승인 도구와 여러 문헌 종합 답변은 아직 없다.
