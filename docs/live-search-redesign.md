# 교황청 실시간 검색과 결과 중심 보관 재설계

2026-11-06. 상태는 **원인 분석·구현 설계 완료, 실행 앱 변경 전**이다. 사용자는 교황청 자체 검색만 허용했다. 기존 대량 수집 중심 계획보다 이 문서를 우선하며, 기존 SQLite 근거 보존 원칙과 GraphDB 읽기 전용 투영 결정은 유지한다.

후속 구현은 [이슈 #14](https://github.com/elmosfire70-saint/holy-naju-search/issues/14)에서 관리한다. 나주 기존 보관 검색/파일 가져오기는 유지하되 새로운 전체 본문 선행 수집은 이번 전환의 필수 단계가 아니다. 나주 자체 온라인 검색은 별도 경로 검증이 필요하며 교황청 검증 결과를 그대로 적용하지 않는다.

## 1. 확인된 원인

| 관찰 | 증거 | 판단 |
|---|---|---|
| 교황청 키워드 검색 4종 모두 0건 | 실제 DB를 읽기 전용으로 열어 메모리에 backup 후 `search(..., source='vatican', refresh=True)` 실행. `공동 구속자`, `공동구속자`, `Mater Populi Fidelis`, `Co-redemptrix` 모두0 | 사용자 제보 재현. 캐시 우회로도 동일 |
| 대상 문헌 자체가 없음 | 제목/URL 직접 SQL 조회0, `/cfaith/` 문헌판0 | 순위 문제가 발생하기 전, 발견·수집 범위에서 누락 |
| 교황청395판은 영어393·이탈리아어2 | 전체668판/15,375문단에서 출처/언어별 집계 | 한국어 원문이 없는 범위에서 한국어 문자열 검색만으로 해결 불가 |
| 기존 모든 교황청 수집 범위가 대상 URL 거부 | `collections.normalize_url`을5개 범위에 적용하면 모두 `outside_collection_paths` | 회칙·교리서·두 공의회로 제한한 패턴에 신앙교리부 경로가 없음 |
| 검색과 웹 수집은 별개 | `server.Handler._post` → `search.search`; 웹은 `/api/collect`에서만 호출 | 검색 버튼·refresh는 실시간 웹 검색이 아님 |
| 키워드는 원문/제목의 문자열 AND, 의미 검색도 로컬 후보만 사용 | `search._ranked_hits`, `_ensure_index`, `semantic._passages` | 명시적인 다국어 용어 확장 없음. 임베딩도 미보관 문헌을 발견할 수 없음 |
| DB 검사 정상 | `PRAGMA quick_check`=`ok`, `PRAGMA foreign_key_check`=[] | 이번 증거에서 DB 손상 징후 없음. 전체 파일/OCR 의미 정확성 검사와는 다름 |
| 빈 결과도 로컬 세대가 같으면 재사용 | `search.search`의 generation 기반 cache key | 웹에 새 자료가 있어도 로컬 세대가 안 바뀌면 계속0. 다만 캐시가 최초 누락의 원인은 아님 |

따라서 문제는 SQLite라는 제품 자체보다 **정해진 보관 자료만 검색하는 제품 설계**, **신앙교리부 미포함**, **한국어 질의와 외국어 발견의 단절**이다. 저장소를 GraphDB로 바꾸거나 문헌 한 건만 수동 추가해도 이 원인은 해결되지 않는다.

### 공식 자료와 자체 검색의 추가 한계

- [신앙교리부 공식 원문](https://www.vatican.va/roman_curia/congregations/cfaith/documents/rc_ddf_doc_20251104_mater-populi-fidelis_en.html)은 2025-11-04 문헌이며 17–22항이 Co-redemptrix 호칭을 다룬다. 검색은 그 용어의 사용뿐 아니라 제한·부정의 문맥도 함께 찾아야 한다.
- [한국어 바티칸 뉴스 기사](https://www.vaticannews.va/ko/vatican-city/news/2025-11/dicastero-nota-maria.html)에는 `공동 구속자`가 나온다. 이는 **문헌 전체의 공식 한국어 번역판이 아니라 보도 기사**다. 최초 원인 조사에서 확인했으며, 앱의 기본 문헌 검색/본문 보관 범위에 자동 추가하지 않는다.
- [교황청 검색 화면](https://www.vatican.va/content/vatican/en/search.html)의 공개 스크립트는 같은 호스트의 `/bin/servlet/solr/search`를 호출한다. 확인한 스크립트는 `/etc/designs/vatican/library/clientlibs/themes/search.min.35a011495c653ace417eb52df66abe09.js`다. 공개 화면용 경로이지 장기 호환성이 보장된 정식 개발자 API로 확인한 것은 아니다.
- 관찰한 요청은 GET, `queryroute=vatican_va-search-main`, `q`, `fq=lang_s:en`, `sort=score desc,id asc`, `rows=10`, `start=0`이다. 화면 코드는 여러 단어를 ` AXNXD `로 연결하고 정확 구절에는 따옴표를 사용한다. 임의 Solr 연산자를 사용자에게서 그대로 받지 않는다.
- 실제 제목 AND 검색과 정확 구절 검색은 영어·이탈리아어에서 해당 원문 대신 2026-01-29 신앙교리부 총회 연설1건을 반환했다. 영어 `Co-redemptrix`는1334건/상위10건에 무관 후보가 많았고, 따옴표 구절은 다른 문헌1건, 한국어 AND는0건이었다. **자체 검색 연결만으로 이번 사례가 해결된다고 주장할 수 없다.** 숫자는 조사 시점의 관찰이지 고정 계약이 아니다.
- 반면 [신앙교리부 공식 전체 문헌 목록](https://www.vatican.va/roman_curia/congregations/cfaith/doc_doc_index.htm)에서 대상 제목과 영어·이탈리아어 등 실제 원문 링크를 확인했다. 이 링크는 [신앙교리부 진입점](https://www.vatican.va/roman_curia/congregations/cfaith/index.htm)의 `Documents: Complete List`에서 발견했다. URL을 모델이 생성하지 않는다.
- [robots](https://www.vatican.va/robots.txt)는 조사 시 `User-agent: *`, `Allow: *`, `Crawl-delay: 2`였다. 구현 시 재확인한다. 공식 화면의 분석 스크립트는 실행하지 않고 같은 호스트 검색 응답만 직접 읽는 방식으로 제3자 추적 요청을 피한다. 교황청 내부 처리 방식을 검증했다는 의미는 아니다.

## 2. 새 기본 흐름

```text
한국어 검색어
  → 로컬 용어 정규화·다국어 검색어 생성
  → 교황청 자체 검색 + 관련 공식 문헌 목록 확인
  → URL/언어/발행 기관 검증·중복 후보 정리
  → 상위 후보 원문을 임시로 읽고 근거 문단 확인
  → 문헌별 관련도 정렬·원문/한국어 번역 표시
  → 표시한 검증 결과의 원문 버전·근거·검색 기록만 로컬 보관
```

기존 자료실 검색은 `보관 자료 검색`으로 유지한다. 기본 `교황청 실시간 검색`은 로컬 DB에 자료가 있거나 없거나 항상 온라인 발견을 시도한다. 과거 결과를 먼저 보여줄 수 있지만 `이전 결과 · 최신 확인 중`으로 명시하고 새 결과와 섞어 표시하지 않는다.

여기서 실시간은 **검색을 누른 시점에 공식 검색/목록과 원문을 확인한다는 뜻**이다. 교황청 색인의 실시간 갱신·모든 문헌의 완전한 발견을 보장한다는 뜻은 아니다.

## 3. 검색 기준

### 질의와 언어

1. 원래 질의를 보존한다. NFC·연속 공백·영문 대소문자·하이픈 표기를 검색용으로만 정규화하고 원문을 수정하지 않는다.
2. 근거 있는 작은 용어 사전을 먼저 사용한다. `공동 구속자/공동구속자` → 영어 `Co-redemptrix/Coredemptrix`, 이탈리아어 `Corredentrice`를 발견용 별칭으로 취급한다. 용어 사전에 출처·수정 버전을 기록한다. 제목 `Mater Populi Fidelis`는 고유 제목으로 검색한다.
3. 제목을 모르는 주제 질의에서는 공식 목록의 제목/설명을 검색한다. 이 사례의 `Marian titles`, `Mary's cooperation ... salvation` 같은 표현은 **넓은 후보 발견용 관련어**이며 정확한 동의어나 교리적 동일성으로 취급하지 않는다. 별칭·관련어 일치 이유를 사용자에게 표시한다.
4. 사전에 없는 질의의 번역/관련어 제안은 기존 로컬 모델만 사용하며 생성 제안임을 기록한다. 모델 불가용이면 이를 표시하고 원문 용어 입력을 허용한다. 외부 모델/검색 엔진으로 대체하지 않는다.
5. UI 표시 언어 한국어와 원문 언어 필터를 분리한다. 한국어 질의라고 외국어 원문을 제외하지 않는다. 사용자가 원문 한국어만 지정하면 그 제한을 명시한다.
6. 정확 구절 모드는 별칭/의미 확장을 하지 않는다. 번역 용어로 넓히는 동작은 별도 옵션이다. 부정·인용·시대 조건은 확장 과정에서 삭제하지 않는다.

### 후보 발견과 공식 목록 보완

- 교황청 자체 검색을 기본 발견 경로로 사용한다. 신앙교리부 자료를 포함하며 회칙·교리서·공의회 경로만 허용하는 기존 수집 정규식을 실시간 발견 경로에 재사용하지 않는다.
- 자체 검색이0이거나 정확 제목이 없을 때, 또는 교리 관련 질의일 때 공식 신앙교리부 문헌 목록을 확인한다. 목록의 제목·날짜·링크만 읽어 질의 관련 후보를 선별한다. 목록 전체 본문을 문헌 DB로 가져오지 않는다.
- 첫 구현은 확인된 신앙교리부 목록과 기존 공식 공의회/교리서 진입점만 지원한다. 다른 부서 목록은 확인 후 추가하며 미지원 범위는 표시한다. 무제한 재귀 크롤링은 하지 않는다.
- 목록에 들어 있는 언어 링크를 사용한다. `_en`을 임의 치환해 존재하지 않는 번역 URL을 만들지 않는다.
- 사용자에게 공식 URL 직접 열기/보관 경로도 제공한다. 색인 미수록 문헌을 사용자가 알려줄 수 있어야 하며, 제목 문자열을 특정 URL로 하드코딩해 이 사례만 통과시키지 않는다.
- 초기 작업 상한 제안은 확장 질의4개, 질의당 최대2페이지(10건/페이지), 관련 목록2개, 본문 검증10개다. 다음 페이지/추가 확인은 명시적 실행으로 이어간다. 상한 도달은 `부분 검색`이며 전체 검색 완료가 아니다. 실제 지연과 누락 평가 후 조정한다.

### 관련도와 근거

- 제목/문서 식별자 정확 일치, 원문 구절·검토된 별칭 일치, 주제 의미 관련 순서로 신호를 구분한다. 교황청 제공 순위를 그대로 정확도로 간주하지 않는다.
- 공식 본문에서 근거를 찾은 결과를 본문 미확인 후보보다 우선한다. 문헌 단위로 중복을 묶고 문헌 안에 일치 문단을 펼친다. 여러 언어판과 보도 재게재를 여러 독립 근거처럼 세지 않는다.
- 유사도는 확률/정확도 점수가 아니다. 의미만 유사한 결과는 `주제 관련 후보`로 표시하며 `정확 용어 일치`와 구별한다. 관련성 판정은 평가 자료로 검토한다.
- 용어를 지지하는 문장만 골라내지 않는다. 경고·부정·옛 문헌 인용과 현재 발행 문헌의 설명을 문맥/날짜/기관으로 구분한다. 종합 AI 답변은 여전히 다음 단계다.
- 결과 카드에는 제목·기관·발표일·원문 언어·검증 시각·발견 경로·일치 이유·공식 URL·공식 문단 번호를 표시한다. 공식 번호가 추출되지 않으면 추출 위치라고 표시하며 번호를 추측하지 않는다.
- 기계 번역은 선택한 근거와 인접 문맥에 한해 로컬 생성하고 `미검토 기계 번역`으로 표시한다. 공식 한국어 번역을 확인하지 못했다는 사실을 숨기지 않는다.

## 4. 무엇을 저장할 것인가

| 대상 | 저장 정책 |
|---|---|
| 질의·조건·확장 내역·검색 시각·성공/부분/실패 | 로컬 검색 실행에 저장 |
| 화면에 표시한 후보의 제목/URL/발견 경로 | 결과 메타데이터만 저장. 본문 미확인은 근거로 사용하지 않음 |
| 본문 확인 후 표시한 관련 문헌 | 정확한 문맥 재확인을 위해 해당 문헌판 전체 원본1개와 추출 버전 보관 |
| 일치 문단·발췌·위치 | 보관 원문 버전에 FK로 연결 |
| 탈락 후보·문헌 목록의 모든 항목 | 본문 영구 보관 안 함. 임시 작업 후 폐기, 실행에는 건수/실패 이유만 기록 |
| 링크된 다른 문헌·각주에 있는 전체 문헌군 | 자동 다운로드 안 함. 사용자가 검색/열기 요청할 때 처리 |
| 번역·임베딩 | 선택된 결과의 필요한 부분만 로컬 생성·재사용 |
| 사용자가 가져온 PDF/TXT/HTML/DOCX | 기존 파일/OCR 보관 기능 유지. 인터넷 전송 금지 |
| 기존668판과 과거 기록 | 그대로 보존. 새 검색은 이를 선행 조건으로 삼지 않음 |

검색 결과의 발췌만 저장하면 나중에 원문 문맥·각주·번역을 대조할 수 없다. 따라서 **검색에 실제 채택한 문헌만 전체 보관**한다. 이것은 전 사이트 사전 수집과 다르다. 본문 확인을 위한 임시 다운로드까지 없앨 수는 없으며, 임시 파일에는 크기/수명 상한을 둔다. 권리/이용 조건이 보관을 허용하지 않으면 URL·메타데이터만 남기고 `오프라인 원문 미보관`으로 표시한다.

## 5. 최소 DB 변경안

SQLite와 `documents → editions → document_versions → passages`, `assets/acquisitions`, `translations`를 재사용한다. 기존 `search_runs/search_hits/search_history`는 로컬 검색과 옛 기록용으로 유지한다. 현재 search_hits는 version/passage NOT NULL이므로 원문 미확인 웹 후보를 억지로 넣지 않는다.

새 마이그레이션에 다음3개 테이블을 추가하는 안이다. 아직 적용하지 않았다.

| 테이블 | 핵심 필드/제약 |
|---|---|
| live_search_runs | UUID PK, query_original, normalized_query, filters_json, expansions_json, policy_revision, model_profile, status, started_at, finished_at, previous_run_id FK, probes_json, coverage_json, error_code. status는 pending/running/completed/partial/failed/interrupted. 네트워크 시도·요청 시각·정규화 요청 URL·응답 건수/해시·오류는 probes에 기록하고 비밀값은 저장하지 않음 |
| live_search_results | UUID PK, run_id FK, rank, canonical_url, language, title_snapshot, issuer_snapshot, published_at, discovery_method, discovered_from, match_kind, verification_status, fetched_at, checked_at, HTTP status/ETag/Last-Modified, asset/body hash, version_id nullable FK, error_code. UNIQUE(run_id, canonical_url, language), UNIQUE(run_id, rank). verified 상태는 version_id 필수. 수집 성공과 인간 관련성 검토 상태는 별도 |
| live_search_evidence | result_id FK, ordinal, version_id, passage_id, start/end, excerpt, match_signals_json. UNIQUE(result_id, ordinal). (version_id, passage_id) 복합 FK, 결과 version과 동일성 제약/검사, 저장 발췌가 원문 slice와 같아야 함 |

- 단순 실행/probe 데이터는 JSON으로 시작한다. 여러 제공자용 추상 계층·Graph 서버·새 벡터 DB·범용 작업 큐는 만들지 않는다.
- 후보 검증 중의 임시 상태와 최종 기록을 분리한다. 실행 종료 후 결과/근거 snapshot을 바꾸지 않는다. 이후 `원문 저장`은 새 실행을 만들어 과거의 본문 미확인 상태를 소급 변경하지 않는다.
- 같은 URL+언어판과 동일 파일 해시는 기존 보관본을 재사용한다. 다른 언어를 동일 버전으로 병합하지 않으며 추적 파라미터 제거는 확인된 것만 적용한다.
- 내용이 바뀌면 새 원문 버전, ETag/Last-Modified/본문 해시가 같으면 기존 버전과 새 확인 시각을 연결한다. 304는 대응하는 기존 보관본이 있을 때만 유효하다.
- 네트워크/모델 호출 동안 SQLite 쓰기 트랜잭션을 잡지 않는다. 파일 임시 저장→해시 검증→기존 가져오기→짧은 결과 커밋 순서로 처리한다. 저장 실패는 성공 결과로 표시하지 않는다.
- 중단된 live 실행은 재시작 시 interrupted로 표시하고 새 실행으로 재시도한다. 기존 ingestion의 미완료 작업/고아 파일도 검사한다. 복구 없이 무조건 성공 처리하거나 참조 파일을 자동 삭제하지 않는다.
- 향후 GraphDB에는 문헌/문단 UUID와 live_search_evidence의 근거를 투영한다. 의미 유사성이나 질의 확장을 검토된 교리 관계로 바꾸지 않는다.

## 6. 재검색·캐시·화면

- `교황청 실시간 검색`은 새 온라인 실행을 만든다. 이전0건/이전 성공 캐시를 이유로 온라인 발견을 건너뛰지 않는다. 발견 URL도 재검증한다.
- `당시 결과 열기`는 네트워크/모델 없이 고정 snapshot을 연다. `보관 자료 검색`은 기존 로컬 검색/캐시를 사용한다. 세 동작의 이름과 실행 시각을 구별한다.
- 파일·추출·번역·임베딩은 해시/모델 버전으로 재사용하되, 이를 최신 웹 발견의 재사용과 혼동하지 않는다. 전체 자료 임베딩을 새 검색마다 만들지 않는다.
- 실패·차단·시간초과는0건이 아니다. 이전 보관 결과를 제공할 때 `온라인 확인 실패 · 과거 보관본`으로 표시한다. 부분 성공 시 실패한 질의/호스트/본문 수와 검색 상한을 공개한다.
- A 연구실형을 유지하고 기본 모드 선택, 진행 단계, 문헌별 결과, 당시 결과/최신 재검색 버튼만 바꾼다. 서버에서 실행 ID를 반환하고 기존 화면이 상태를 polling하도록 한다. 개인 PC 작업자1개와 취소/중복 제출 방지를 먼저 구현한다.
- 최소2초 요청 간격과 후보 본문 검증 때문에 전체 완료가 수십 초 이상 걸릴 수 있다. 후보 표시/본문 확인/번역 완료를 구분하고 기존 로컬3초 목표를 실시간 웹 전체 처리 목표로 사용하지 않는다.

## 7. 안전한 네트워크 범위

- 첫 구현의 자동 요청 대상은 `www.vatican.va`의 확인된 검색/목록/문헌 경로다. `press.vatican.va`는 기존 보관 URL 정책과 별개로 robots·본문 형식 검증 후 지원한다. `www.vaticannews.va`의 기사 검색/보관은 기본 제외한다.
- 사용자 질의/URL은 비신뢰 입력이다. HTTPS·정확 호스트·443·허용 경로·길이·MIME·응답 크기를 검증한다. 사용자정보가 있는 URL, 사설/루프백 대상, 임의 포트와 리디렉션은 거부한다. 새 호스트를 자동 신뢰하지 않는다.
- 호스트별 robots/요청 간격을 지키고 401/403/429/CAPTCHA에서 멈춘다. 우회하지 않는다. 검색 JSON 오류/HTML 차단 페이지/빈 본문은 명시적 실패다. 사이트 약관/보관 조건도 별도 확인한다.
- 공식 페이지의 JavaScript나 추적 코드를 실행하지 않고 텍스트/JSON만 읽는다. 페이지 내부 지시문은 명령이 아니다. 원본 HTML은 실행하지 않는다.
- 외부 일반 검색 서비스·유료 API·외부 모델 호출 없음. 사용자 파일·기존 검색 기록·원문을 다른 서비스로 전송하지 않는다. 로컬에서 만든 검색어만 교황청에 전달한다.

## 8. 전환 순서와 완료 기준

1. **발견 경로**. 교황청 공개 검색의 파라미터/응답 parser와 공식 목록 보완을 구현한다. 고정 fixture와 실제 공개 질의에서 제목/용어 변형으로 대상 문헌을 발견하는지 검증한다. 공식 검색이 대상 문헌을 안 내놓는 fixture도 포함한다.
2. **결과 중심 보관**. 일관된 SQLite+assets 백업 후 복제본에 마이그레이션한다. 세 테이블과 원문 확인/중복 재사용/버전 보존을 추가한다. 결과로 채택하지 않은 문헌의 영구 본문0개를 검사한다.
3. **한국어·UI 통합**. 로컬 용어 확장·문헌 그룹·확인 시각·미검토 번역·진행/실패/오프라인 상태를 연결한다. 새 모드가 검증되기 전 기존 모드를 제거하지 않는다.
4. **회귀와 전환**. 기존 검색/기록/파일/OCR/번역 테스트, 마이그레이션 FK/내용 해시 비교와 브라우저 핵심 흐름을 통과한 뒤 기본 검색 모드를 바꾼다. 롤백은 구 앱+일관된 백업을 별도 경로로 열어 수행하며 새 자료를 덮어쓰지 않는다.

필수 합격 사례는 다음과 같다.

- 빈 신규 DB에서도 `공동 구속자`, `공동구속자`, `Co-redemptrix`, `Mater Populi Fidelis`의 일반 검색으로 실제 공식 문헌을 발견한다. 제목 질의는1위, 용어 질의는상위5위에 목표 문헌과17–22항의 관련 근거를 보여주는 것을 이 사례의 기준으로 삼는다. 이는 전체 정확도100% 선언이 아니다.
- 대상 URL 하드코딩 없이 목록에서 링크를 찾고, 자체 검색0/누락·하이픈 잡음·언어 차이를 재현한다. 정확 구절 모드는 확장하지 않는 별도 기대값을 가진다.
- 스니펫만 존재하거나 본문이 차단되면 `본문 미확인`, 검색 장애면 `실패/부분`으로 표시한다. 결과0과 혼동하지 않는다.
- 같은 문헌이 여러 질의/언어/경로에서 나와도 언어판·원문 버전·문헌 그룹이 정확하다. 새 실행은 온라인 요청을 하고 동일 본문 파일은 중복 저장하지 않는다.
- 원문이 바뀌어도 이전 기록·번역의 근거는 그대로 열린다. 인터넷이 꺼지면 당시 기록은 열리되 최신 확인 성공으로 표시하지 않는다.
- 신앙교리부 문헌, 공의회, 교리서, 회칙과 잡음/부정/없는 용어를 포함한 독립 평가 질문으로 누락·정렬·근거·번역을 검토한다. 이번 문헌1건의 성공을 전체 평가 통과로 간주하지 않는다.
- 무관 본문/전 사이트 크롤링0, 승인되지 않은 호스트 요청0, 사용자 파일 외부 전송0을 요청 기록/네트워크 차단 테스트로 검사한다.

## 9. 이번 검증과 미완료

실행한 검사는 실제 `search()`의 메모리 복제 재현, 직접 SQL 집계, 수집 경로 거부 검사, SQLite quick_check/FK 검사, 교황청 자체 검색6회와 공식 목록/원문 확인이다. 사용자 증상 검사는 의도대로 AssertionError로 실패했으며 **아직 수정된 앱의 통과 증거가 아니다**. 앱의 기본 UI는 hybrid이지만 이번 수치 재현은 keyword 모드다. hybrid가 다른 관련 문헌을 반환할 가능성과 대상 문헌이 DB에 없어 반환할 수 없는 사실을 구분한다.

실행 앱 소스·DB 스키마·기존 자료는 이번에 변경하지 않는다. 이번 문서는 설계 작업이며, 본문 임시 저장/자동 정리·동의어·실시간 검색·UI 및 신규 마이그레이션의 실행 검증은 위 단계의 미완료 작업이다.
