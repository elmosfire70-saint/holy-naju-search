# 발견 목록·제한 수집 검증

2026-10-31, 이슈 #10의 범위다. 전체 문헌 수집이나 1차 출시 완료 보고가 아니다.

## 구현과 경계

기존 SQLite/가져오기/검색을 재사용해 범위·발견 목록 페이지/문헌 URL·시도·원문 버전 연결을 추가했다. CLI는 목록/문헌 각각 최대 20개, 화면 버튼은 각각 1개만 처리한다. 검색 요청과 별개이며 자동 반복 예약이나 새 번역/임베딩 생성은 없다.

수집 범위는 고정 공식 호스트·경로·언어와 실제 href로 제한한다. 나주 목록의 q/t 문맥과 fragment는 제거하고 메시지 idx와 페이지 번호로 중복을 구분한다. 교리서는 차례의 본문 __P 링크만 받는다. 이미 보관한 공식 URL/언어는 기존 버전에 연결한다. 가져온 파일과 같은 제목이라는 이유로 병합하지 않는다.

robots 확인·최소 2초 간격·25MiB 응답 상한을 적용한다. 프록시/자동 리디렉션을 사용하지 않고, robots 실패·접근 제한·HTTP 200 차단 화면에서는 중단한다. 목록 형식 변경/빈 목록/반복 본문은 완료가 아닌 문제로 남긴다. 전체 자동 수집에서 로그인·캡차·비공개 API를 사용하지 않는다.

## 실제 발견/보관 상태

아래는 이번 실행 종료 시 로컬 DB의 상태다. 발견 URL은 서문·절 단위를 포함하며 전체 저작물 수나 검토 완료 문헌 수가 아니다.

| 범위 | 발견 문헌 URL | 보관 연결 | 대기 | 목록 처리 |
|---|---:|---:|---:|---|
| 나주 한국어 | 272 | 4 | 268 | 발견한 연결 14/14페이지 처리 |
| 영어 교리서 본문 | 374 | 2 | 372 | 차례 1/1 처리 |
| 기존 영어 회칙 후보 | 3 | 2 | 1 | 고정 후보만 등록 |
| 제1차 공의회 이탈리아어 | 2 | 2 | 0 | 목록 1/1 처리 |
| 제2차 공의회 영어 | 16 | 2 | 14 | 목록 1/1 처리 |
| 트리엔트 및 이전 | 미확인 | 0 | 미확인 | 공식 전체 진입점 미확인 |

등록한 원문 중 이번에 새로 보관한 것은 나주 3건, 교황청 4건이다. 기존 공식 자료 5건과 사용자 OCR 파일 1건을 포함해 보관소는 문헌/파일/원문 버전 각 13개·문단 1,062개다. 실제 수집 시도 24개(목록 17개+새 원문 7개)가 정상 처리됐다. 실제 실패를 관찰한 것으로 보고하는 것이 아니며 실패/차단 사례는 합성 테스트에서 검증했다.

나주의 272는 목록에서 발견한 URL이며 서문 같은 관련 항목도 포함한다. 14페이지의 당시 연결 처리가 끝났다는 뜻이지 향후 추가 메시지·삭제·미노출 자료까지 포함하는 영구적 전체성 보장은 아니다. 제1차의 두 이탈리아어 파일도 다른 언어·모든 과거 공의회 확보 완료라는 뜻이 아니다.

## 공식 근거 조사

[공식 공개 목록 조사](source-discovery-research.md)에 교황청 직접 링크·언어·PDF 예외·한국어 공식 자료와 미확인 범위를 기록했다. 현재 자동 경로는 영어/이탈리아어 HTML 우선이며 다른 언어·PDF 및 새 호스트를 자동 추가하지 않는다. 주요 회칙은 기존 후보 3건일 뿐 전체 주요 회칙의 사용자 확정 목록이 아니다.

나주 [목록](https://najumary.or.kr/Messages1/)과 `?page=2`의 실제 href를 확인했다. [robots](https://najumary.or.kr/robots.txt)는 확인 시 공개 목록을 허용했다. Insane Search는 짧은 344바이트 robots를 challenge로 분류했지만, 기록된 실제 본문은 정상 robots 지시였고 직접 요청의 200/text/plain으로 구분 확인했다. 도구의 성공/실패 라벨을 사이트 차단 사실과 동일시하지 않았다. robots에 있는 다른 사이트 주소는 지시로 실행하거나 허용 호스트에 추가하지 않았다.

[교황청 robots](https://www.vatican.va/robots.txt)의 Allow와 Crawl-delay 2를 확인했다. robots 허용은 재배포 허가가 아니며 [교황청 이용 조건](https://www.vatican.va/content/vatican/en/legal-notes.html)을 확장 이용 허가로 해석하지 않는다. 원문/목록/DB는 Git 제외 개인 데이터에만 보관한다.

## 검증 증거

- 전환 전 SQLite backup API로 `data/backups/before-collections-v4.sqlite3`를 생성했다. 버전 3에서 4로 전환한 뒤 기존 문헌/문단/번역/기록 ID와 모든 기존 원문 텍스트·본문 해시·검색 hit snapshot을 백업과 대조해 보존을 확인했다.
- 합성 목록에서 중복 URL·범위 밖 링크·페이지 반복·빈 목록·robots 실패/거부·403·HTTP 200 차단 화면·단일 작업자 잠금·한도·실패 재시도·이전 작업자 중단 상태 재개를 검증했다.
- 원문 갱신 시 새 버전, 이전 검색 snapshot 유지, 실패한 갱신에서도 이전 보관 연결 유지와 버전 3 마이그레이션을 검증했다.
- Chrome에서 범위별 실제 건수·진입점 미확인/자동 버튼 없음·목록→보관 버전→문단 열기·실제 제한 수집 1건과 390px 가로 넘침 없음을 확인했다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node --check holy_naju/web/app.js
.\.venv\Scripts\python.exe -X utf8 scripts/import_documents.py check
git diff --check
```

전체 53개 테스트 통과, 생략 없음. 실제 보관소 무결성은 `ok=true, problems=[]`다. 브라우저 검증 코드는 개인 데이터 `data/ui-review/output/playwright/collection-check.js`, 수집 실행 보고는 `data/discovery-research/`, 목록/문헌 증거는 `data/library/collection-evidence/`에 있다.

## 아직 남은 일

현재 발견한 대기 본문의 계속 수집, 공식 주요 회칙 범위 확정, 다른 언어/PDF·이전 공의회 진입점 조사, 완전한 주기 갱신·삭제 감지·파일 가져오기 중 전원 장애 복구·백업 복원·대규모 성능/품질 평가는 미완료다. 수집 작업 상태 재개 테스트가 파일 보관의 모든 장애 복구를 입증한 것은 아니다. 목록 화면은 문제 우선 최대 200항목만 보여준다. 새 형식이 나타나면 실패를 확인하고 파서를 검증한 뒤 재시도한다. 2차 AI 종합 답변은 구현하지 않았다.
