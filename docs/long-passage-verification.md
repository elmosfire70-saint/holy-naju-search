# 긴 문단 임베딩 수정 검증

2026-10-31, 이슈 #13. 긴 회칙 문단 하나가 전체 결합 검색을 키워드로 대체시키던 오류를 수정했다. 검색 실행 안정성의 검증이며 인간 관련성/번역 품질의 출시 통과는 아니다.

## 원인과 수정

이전 평가의 E01에서 Redemptoris Mater의 한 문단을 제목과 합친17,298자 입력이 로컬 Qwen 임베딩의4096문맥을 넘었다. 배치16개와 해당 문단 단독 요청 모두 HTTP400/input length exceeds context length를 반환했다. 모델/API 장애로 추측하지 않고 저장된 실제 오류를 확인했다. 원문 본문 자체는17,264자다.

수정은 `holy_naju/semantic.py`의 입력 준비와 부모 문단 점수 결합에만 적용했다.

- 제목+원문 입력을 최대2000 UTF-8 바이트,128문자 겹침의 구간으로 나눈다. 모든 문자를 유지하고 구간별 원문 범위를 계산한다. 모델별 기존 입력 접두사는 유지한다.
- 구간마다 임베딩/코사인 유사도를 계산하고 최대값으로 부모 문단을 한 번만 순위에 넣는다. 평균으로 긴 문단의 끝 근거를 희석하거나 같은 문단으로 결과 상한을 채우지 않는다.
- 선택 구간의 문단 상대 범위는 `retrieval_signals.semantic.passage_range`에 기록한다. 기존 문단/버전 ID·원문 전체·파일/위치·검색 snapshot은 유지한다. DB 스키마/추출기·원문을 바꾸지 않았다.
- 검색 파이프라인을 `hybrid-rrf-segment-max-2`로 올려 이전 순위를 재사용하지 않는다. 같은 모델 프로필·동일 입력의 벡터 의미는 같으므로 기존 `title-passage-query-instruct-1` 프로필과 입력 해시를 재사용한다. 이전 검색/벡터/문단 연결은 삭제하지 않는다.

바이트 제한은 토큰 수의 수학적 보장이 아닌 보수적 입력 정책이다. `truncate=false`, 모델 digest 확인, 실패 진단/키워드 대체와 원격 모델 거부는 그대로다. 문맥 한도를 늘리거나 새 모델/의존성·토크나이저·DB를 추가하지 않았다. 구간은 문장 경계 분할이 아니며 최대 구간 점수의 관련성/긴 문단 편향은 인간 평가가 필요하다. 현재 발췌/강조와 전체 원문 화면은 기존 방식이며 선택 구간 자동 스크롤을 추가한 것은 아니다.

## 실패 재현과 실제 문단

길이 제한이있는 합성 모델로 긴 문단 끝에만 근거가있는 사례를 먼저 실행했다. 수정 전에는 `retrieval=keyword`로 대체되어 회귀 테스트가 실패했다. 수정 후에는 결합 검색으로 부모 문단을 한 번 반환하고 끝 근거가 선택 범위에 포함되며 원문이 그대로인 것을 확인했다.

실제로 실패한 문단 ID `d1eb3449-bef1-4479-8193-b2f33218651c`, 버전 `436c79b4-eb33-4f70-83fb-0d8f545941aa`의 전체 입력은10개 구간으로 처리됐다. 최대 입력2000바이트,1024차원 벡터10개를 반환했다. 같은 모델 digest `ac6da0dfba84a81fdbfbaf330198c33cd77c4cdfc53e8bc50eb581914a15621d`, num_ctx4096에서 잘라내기 없이 성공했다.

한국어/영어/이모지/결합 문자·긴 제목의 구간 범위 무누락, 모델/원문 변경, 필터·실패 대체·벡터 검증, 이전 순위 무효화와 동일 입력 벡터 재사용, 과거 결과 보존도 자동 테스트로 확인했다.

## 확대 보관소 재평가

이전 평가 보관소를 새로 복제해20:13:52~20:15:14 KST에 실행했다.668개 문헌판·15,375개 문단이 같은 질문/필터/상한20으로 평가됐다.

| 요청 방식 | 정상 | 키워드 대체 | 미실행 |
|---|---:|---:|---:|
| 키워드/구절 | 50 | 0 | 0 |
| 로컬 결합 | 42 | 0 | 8 |

결합 미실행8개는 원래 결합 검색을 사용하지 않는 구절 문항이다. 이전35개 정상/1개 대체/오류 이후6개 미실행이었던 주제 요청42개가 모두 정상 처리됐다. 실행 상태이며 정답률이 아니다.

`data/evaluation/check-segment-fix.py`의 대조 결과는 다음과 같다.

- 원문/문헌/언어판/파일/작업/유입/페이지/문단/번역 행이 복제 전과 같다. 과거 검색/결과/기록·임베딩 행은 모두 남았다.
- 키워드50개는 기존 실행 ID를 재사용했다. 이전에 정상 실행됐던 결합35개는 새 파이프라인의 다른 실행 ID로 생성됐다. 과거 실행은 계속 열린다.
- 전체 현재 문단의15,403개 입력 구간이 임베딩 DB에 연결됐다. 벡터는15,670개에서15,779개로 늘었으며 동일 입력의 기존 벡터를 재사용했다.
- 검색 hit989개의 원문 버전/발췌/구간 범위와 중복 문단 없음이 일치했다. 임베딩 추론을 호출하면 실패하도록 막은 상태에서50+42=92개 요청이 같은 실행 ID로 재사용됐고 벡터 수는 늘지 않았다.
- 보관소 무결성은 `ok=true, problems=[]`였다. 새 검토 후보940개/고유817문단,50문항 모두pending/grade=null이며 지표 평균null·출시false다. 새 번역을 생성하지 않았다.

보고/검토 자료와 대조 결과는 Git 제외 `data/evaluation/quality-2026-10-31T11-13-46.489594+00-00-f54c35f7/`의 `report/`, `segment-check.json`에 있다. 실제 연구 보관소로 평가 벡터/검색 기록을 복사하지 않았다. 첫 실제 의미 검색은 필요한 입력의 로컬 임베딩 생성 시간이 든다.

## 화면과 실제 앱 적용

평가 보관소의8768서버를 Chrome에서 확인했다. E01 회칙 검색이 키워드 대체 없이 결합 결과를 재사용했고, 실패했던 원문17,264자 전체·공식 출처 링크와 이전 검색 실행을 열었다. 브라우저 오류/경고는0개였다. 캡처/검증 코드는 `data/ui-review/output/playwright/segment-fix-search.png`, `segment-fix-check.js`에 있다. 평가 서버는 검증 후 종료했다.
