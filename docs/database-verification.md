# 문헌 DB와 파일 가져오기 검증

2026-10-31. 스키마 버전 1 및 가져오기 API/CLI 검증 기록이다.

## 구현

- SQLite 표준 라이브러리를 사용하고 문헌 DB와 파일은 로컬 보관소에 둔다.
- 문헌·문헌판·파일·가져오기 이력·원문 버전·페이지·문단은 UUID로 식별하고 외래 키로 연결한다.
- 같은 바이너리는 SHA256으로 중복 제거한다. 서로 다른 공식 URL의 문헌을 같은 파일이라는 이유로 자동 병합하지 않는다.
- 정상 추출은 같은 파일·문헌판·파서/추출기·OCR 프로필에서 재사용한다. 원문 변경·OCR 재처리 결과는 별도 버전으로 보존한다.
- 같은 과거 버전을 다시 가져와도 새 원문 버전 포인터를 되돌리지 않는다.
- 실패 파일의 보관 상태와 작업을 남긴다. 문헌·버전·문단 쓰기는 트랜잭션으로 롤백한다.

## 실제 자료 검증

기존에 검증한 공식 HTML 5건을 CLI로 가져왔다. 제1차/제2차 공의회 대표 문헌, 교리서 일부, 회칙, 나주 메시지다. 생성한 한국어 스캔 PDF 1건도 가져오고 다시 가져왔다.

| 항목 | 최종 개수 |
|---|---:|
| 문헌 / 문헌판 / 보관 파일 / 원문 버전 | 각각 6 |
| 근거 문단 | 468 |
| 추출 페이지 | 1 |
| 가져오기 이력 / 작업 이력 | 각각 7 |

공식 문헌 전체의 수집 결과가 아니다. 스캔 재가져오기에서 reused_asset 및 reused_version이 true이고 문헌·파일·버전 ID가 유지되는 것을 확인했다.

`scripts/import_documents.py list`와 `check`를 실행했다. 점검 결과는 `ok: true`, `problems: []`였다. DB의 모든 문단에 대해 정규화 본문의 start_offset/end_offset으로 재구성한 텍스트가 저장 문단과 일치하는 것을 확인했다.

## 자동 검증 범위

명령은 `.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v`다.

최종 결과는 DB 테스트 10개와 기존 추출/OCR 테스트 8개, 총 18개 통과이며 생략된 테스트는 없다. CLI show에서 스캔의 페이지와 문단 연결을 재확인했고 `git diff --check`도 통과했다.

- 초기화 재실행과 외래 키 제약.
- 같은 파일을 다른 이름으로 가져올 때 영구 ID·결과 재사용 및 이력 기록.
- 같은 URL의 본문 변경과 과거 버전 재가져오기.
- 같은 바이너리의 서로 다른 출처 문헌 구별과 명시적 문헌판 연결.
- 문단 저장 실패를 주입한 롤백과 재시도.
- 빈 파일 추출 실패 시 원본·실패 이력 보존.
- 보관 파일 손상과 중단된 복사 파일의 탐지.
- OCR 데이터 부족 상태에서 재처리한 새 버전과 원래 페이지 이력 보존.
- 지원하지 않는 미래 스키마 버전의 비파괴적 거부.
- 기존 HTML·PDF·TXT·DOCX·OCR 회귀 검사.

Windows 샌드박스의 임시 폴더 권한 제한을 피해 권한 있는 테스트 실행 환경을 사용했다. 테스트 자료는 임시 폴더, 실제 가져오기 자료는 `data/library`에만 저장한다.

## 남은 범위

검색 색인·검색 기록 재사용·번역·웹 화면·GraphDB 연결은 아직 구현하지 않았다. 메타데이터는 입력자 선언 또는 자동 추출 후보이며 공식 발행 여부와 공식 문단 번호를 자동 보증하지 않는다. OCR 본문 교정 UI, 자동 중단 재개/미등록 파일 정리, 백업 복원 및 동시 작업 부하 검증은 후속 과제다.
