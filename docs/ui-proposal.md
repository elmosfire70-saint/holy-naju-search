# 새 검색 화면 검토안

현재는 사용자 선택을 위한 시안이다. 확정된 UI나 실제 검색 화면이 아니다. 이슈 [#8](https://github.com/elmosfire70-saint/holy-naju-search/issues/8)에서 선택을 기록한다.

## 비교할 질문

검색 결과와 원문/한국어 번역을 동시에 보는 연구실형이 편한가, 질문부터 시작하는 포털형이나 읽기를 중심에 두는 문헌형이 편한가?

| 안 | 배치 | 맞는 사용 방식 | 고려할 점 |
|---|---|---|---|
| A 연구실형 | 왼쪽 메뉴·가운데 결과·오른쪽 원문/번역 | 여러 근거를 고르면서 대조 | PC에서는 넓은 창이 유리 |
| B 검색 포털형 | 큰 검색창·세로 결과 목록·아래 근거 | 검색부터 차례로 접근 | 결과와 근거를 오갈 때 스크롤 증가 |
| C 문헌 읽기형 | 넓은 원문/번역·오른쪽 결과 목록 | 긴 문헌을 계속 대조 | 검색 결과 탐색의 비중이 작음 |

제안은 A를 기본으로 하는 것이며 아직 사용자 확정은 아니다. 비교 중 다른 안의 검색창이나 읽기 영역을 조합해도 된다. 1100px 이하에서는 원문/번역을 세로로, 760px 이하에서는 결과와 근거도 세로로 배치한다.

## 실행

이 시안 파일은 `prototype/ui-layout-review` 브랜치에만 둔다. 저장소 루트에서 다음 한 명령으로 연다.

```powershell
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory docs
```

- [A 연구실형](http://127.0.0.1:8765/ui-prototype.html?variant=A)
- [B 검색 포털형](http://127.0.0.1:8765/ui-prototype.html?variant=B)
- [C 문헌 읽기형](http://127.0.0.1:8765/ui-prototype.html?variant=C)

하단 좌우 버튼 또는 입력 요소 밖의 좌우 방향키로 전환한다. 배치 선택은 URL에 남고 기타 예시 상태는 새로고침하면 초기화된다. 빌드나 패키지 설치가 없고 실제 앱에 배포하는 파일이 아니다.

## 공통으로 지킬 흐름

- 검색 결과는 문헌 이름·출처·언어·발표일·원문 위치를 함께 보여준다. 의미 점수를 정답 확률로 표시하지 않는다.
- 보관 원문과 공식 사이트의 현재 원문을 구분한다. 추출 블록과 공식 문단 번호를 혼동하지 않는다.
- 생성 번역은 로컬 생성·미검토·공식 번역 아님을 명시한다. 실패해도 원문은 읽을 수 있다. 한국어 원문을 번역으로 표시하지 않는다.
- 저장 결과 재사용, 모델 비가용 시 키워드 대체, 정상 빈 결과, 검색 실패를 각각 표시한다.
- 검색 기록의 당시 결과 열기와 현재 보관 자료로 재검색을 구분한다. 재검색은 사이트 재수집이 아니다.
- 자료실에서는 샘플/전체 수집과 부분 추출·OCR 검토 상태를 구분한다. 출처 분류를 동일한 권위·승인 상태로 표현하지 않는다.

실제 API의 검색·필터·history/get_run·문헌 버전·문단 번역을 후속 UI에서 연결한다. 문헌별 묶기, 번역 검토/수정 도구, 공식/보관 파일 열기는 별도 구현과 검증이 필요하다. 2차 종합 AI 답변은 넣지 않는다.

## 시안의 경계

모든 문장·건수·날짜·ID·검색 기록은 합성 예시다. 사용자가 입력한 질문과 무관한 고정 예시를 표시하므로 검색 성공이나 품질 평가로 간주하지 않는다. 실제 원문·DB를 읽거나 저장하지 않고 모델도 호출하지 않는다. 파일 가져오기·공식 링크·근거 복사 버튼은 명시적으로 비활성화했다. 고급 필터는 배치만 보여준다.

## 검토 상태

2026-10-31, Chrome 1600×1000 및 390×844에서 배치를 확인했다. 선택한 결과 제목의 대비 문제를 발견해 수정 후 재검증했다.

- 3안 전환과 variant URL의 새로고침 유지.
- 입력창 안에서는 방향키를 가로채지 않고, 입력 요소 밖에서는 좌우 배치 전환.
- 번역 실패 상태에서도 원문 유지, 키워드 대체 안내, 정상 빈 결과와 검색 실패 구분.
- 당시 기록 열기와 현재 보관 자료 재검색, 자료실의 부분 추출·OCR 미검토 표시.
- 입력한 HTML 문자열을 실행하지 않고 텍스트로 유지.
- 390px 폭의 A/B/C 모두 가로 넘침 없음.

브라우저 단언 검증은 Playwright CLI의 파일 입력 방식으로 실행해 통과했다. Windows에서 긴 코드 문자열 전달이 구문 오류를 내어 `--filename`으로 전환했다. 검증 코드와 캡처는 Git 제외된 `data/ui-review/output/playwright/`에 보관한다. 재실행 명령은 해당 데이터 폴더에서 `playwright-cli -s=holy-ui-review run-code --filename output/playwright/check.js`다. 이는 UI 시안 조작 검사이며 실제 검색·번역·DB 통합 테스트가 아니다.

시안 script의 `node --check` 구문 검사, 기존 `python -X utf8 -m unittest discover -s tests -v` 38개와 `git diff --check`가 통과했다. 브라우저 콘솔 오류/경고는 없었고 마지막 페이지 로드의 요청은 로컬 시안 GET 1개뿐이었다.

사용자가 아직 안을 선택하지 않았으므로 실제 UI 구현은 시작하지 않았다. A를 권장하지만 배치 선택이나 안별 조합을 확인받아야 한다.
