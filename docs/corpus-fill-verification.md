# 발견 원문 이어 수집·확대 보관소 검증

2026-10-31, 이슈 #11. 기존 수집기를 사용해 이미 발견한 대기 원문 655개를 모두 처리했다. 새 호스트·언어·목록을 추가하거나 1차 출시를 완료한 작업은 아니다.

공식 URL 667개와 기존 한국어 OCR 시험 문서 1개를 포함해 문헌·언어판·파일·원문 버전은 각각 **668개**, 문단은 **15,375개**다. 언어판은 한국어273·영어393·이탈리아어2개다. 원본 파일 합계는220,946,406바이트이며 검증 시 SQLite 파일은50,577,408바이트였다. DB 파일 크기는 후속 검색·기록 생성에 따라 변한다.

URL은 서문·절 단위를 포함한다. 나주272를 서로 다른 메시지272개, 교리서374를 독립된 책374권으로 해석하지 않는다. 현재 발견 URL의 대기가0이라는 뜻이지 나주 사이트의 영구적 전체성·모든 언어·향후 메시지·모든 공의회 확보를 보장하지 않는다. 회칙3개도 전체 주요 회칙의 확정 목록이 아니다. 트리엔트 이전의 진입점 미확인은 문헌 부재 판정이 아니다.

## 수집 실행과 안전 경계

- 실행 전 SQLite backup API로 `data/backups/before-corpus-fill-20261031.sqlite3`를 새로 보관했다. 시작 시 디스크 여유는164.37GiB였다.
- 18:08:27~18:30:25 KST에 기존 대기655개를 나주→제2차→회칙→교리서 순서로 직렬 처리했다. 제1차2개는 기존 보관본을 유지했다. 이번655시도는 모두정상 종료했고 실패·차단·남은 실행 상태는0이다.
- 기존 `collect(..., pages=0, documents=1)`을 반복하고 실행 시작 당시 대기 수를 상한으로 고정했다. 공유 PublicClient의 robots 확인·호스트별 최소2초 간격·25MiB 응답 상한을 유지했다. 한 항목의 오류나 디스크512MiB 미만이면 자동 반복을 멈추도록 했다. 실제 차단을 우회하거나 인증·외부 모델 API를 사용하지 않았다.
- 새 번역·임베딩을 생성하지 않았다. 모델 출력은 기존 번역5개·임베딩948개·문단 임베딩 연결936개 그대로다. 새 원문은 키워드 색인에 반영됐으며 확대 자료의 의미 검색 임베딩 생성·품질 평가는 별도다.
- 원문·DB·백업·시도 로그·검증 스크립트·화면 캡처는 Git 제외 `data/`에만 보관한다. 제품 코드·DB 스키마·의존성은 변경하지 않았다.

## 무결성과 기존 근거 보존

`data/audit-corpus.py`로668개 버전의 원본 SHA256·추출 본문 SHA256·전체 문단 결합·15,375개 문단의 본문 오프셋을 대조했고 불일치가없었다. 나주272개는 보관 HTML의 `.board_txt_area`에서 비본문 노드를 제외한 텍스트를 추출 본문과 공백 정규화 후 전수 비교했다. 결과는 `data/corpus-fill/audit-668.json`에 있다.

이 검사는 이미지에만 있는 글자·신학적 사실·번역 의미의 정확성을 입증하지 않는다. 교황청 HTML의 본문/각주가 의미상 모두 보존됐는지에 대한 전수 인간 검토도 아니다. 문헌668개는 모두 메타데이터 `needs_review` 상태다. 공식 문단 번호 대신 추출 블록 번호인 경우 화면에서 구분한다.

`data/verify-corpus-preservation.py`는 실행 전 백업의 문헌/언어판/파일/작업/유입/버전/페이지/문단과 색인 세대·검색 실행·검색 hit snapshot·검색 기록·번역/임베딩 행이 현재 DB에 그대로 있는지 대조했다. 기존13개 원문·1,062개 문단·29개 검색 실행·148개 hit·54개 기록은 모두 유지됐다. 수집 작업의 URL·출처·언어와 연결 버전의 대응도667개 모두 정상이다. 결과는 `data/corpus-fill/preservation.json`에 있다.

`scripts/import_documents.py check`는 `ok=true, problems=[]`였다. SQLite·외래 키·원본 해시·미등록 파일·중단 가져오기 작업을 점검했다. 백업을 실제 운영 보관소에 복원하거나 전원 장애를 재현한 검증은 이번에 하지 않았다.

## 검색과 화면 검증

`data/check-corpus-search.py`에서 나주 한국어 `사랑 기도`, 교리서 영어 `Eucharist`, 공의회 영어 구절 `Lumen gentium`, 제1차 이탈리아어 `Dio`, 가져온 한국어 OCR 구절 `하루를 시작합니다`를 검사했다. 출처/언어/문헌 종류 필터·근거 발췌의 원문 위치·같은 검색 ID/동일 hit 재사용이 모두 통과했다.

각 조건1회 측정에서 재사용은31.45~52.37ms였다. 첫 한국어 신규 검색은 전체 키워드 색인 갱신을 포함해2,263.60ms, 이후 다른 조건의 신규 검색은33.81~54.35ms였다. 다섯 조건의 기능 점검 표본이며 p95·대규모 정확도·한국어 다국어 의미 검색 성능으로 일반화하지 않는다. 결과는 `data/corpus-fill/search.json`에 보관했다.

실제 Chrome의 `corpus-check.js`에서 다음을 확인했다.

- 보관668건 표시, 나주 키워드 검색20개 근거와 동일 결과 재사용.
- 검색 기록 열기, 수집 전 검색 실행 ID와 당시 원문 열기.
- 수집 전 저장 한국어 번역과 미검토 표시를 새 모델 호출 없이 열기.
- 위5범위의 발견=보관=완전 추출 건수·대기0·문제0 표시. 이전 공의회 미확인/자동 수집 버튼 없음.
- 교리서 상태 목록→보관 버전→문단·출처 URL·보관 파일 연결.
- 390px의 검색·자료실·검색 기록에 가로 넘침 없음. 브라우저 오류/경고0개.

첫 화면 검사는 기록 응답이 오기 전에 이전 `.original` 요소를 읽어 안내 문구 검사에 실패했다. 실제 스냅샷과 `openRun` 경로로 응답 후 정상 표시를 확인했고, 검증 스크립트의 대기 조건만 보완해 재실행 통과했다. 앱 코드는 수정하지 않았다. 코드/캡처는 `data/ui-review/output/playwright/corpus-check.js`, `corpus-desktop.png`, `corpus-mobile.png`에 있다.

## 다음 단계와 미완료 범위

검색 정확도가 최우선이므로 다음은 확대된 자료에서 인간 검토 평가 문항·정답 근거를 준비하고 한국어 다국어 검색/번역을 재평가하는 단계다. 이탈리아어 번역의 오역·제3언어 혼입 문제는 해소됐다고 주장하지 않는다. 다른 언어/PDF·주요 회칙 범위 확정·트리엔트 및 이전 조사·역사 스캔 OCR·메타데이터 검토·갱신/복원·출시 성능 판정도 남아 있다. 여러 문헌을 종합하는2차 AI 답변은 아직 시작하지 않았다.
