# Holy Naju Search 구현 계획

2026-10-31. 1차·2차 기능 범위는 사용자 확인을 반영했다. 세부 성능·모델·화면과 문헌 목록은 구현 전 샘플 조사로 구체화한다.

## 확정된 요구사항

- 기존 정적 앱과 독립적인 새 개인 PC용 앱.
- GitHub 저장소 `elmosfire70-saint/holy-naju-search`에서 작업 관리.
- 한국어 중심 검색. 교황청 외국어 원문과 한국어 번역을 함께 확인.
- 나주는 사랑의 메시지 전체를 첫 수집 대상으로 한다.
- 교황청은 교리서·공의회 문헌·주요 회칙을 첫 대상으로 한다. 주요 회칙은 수집 목록으로 확정한다.
- 공의회 문헌은 제2차 바티칸 공의회뿐 아니라 그 이전 공의회도 대상에 포함한다. 공의회별 공식 공개 문헌 목록과 미확보 자료를 구분하며, 제2차 이전 자료가 모두 온라인에 있다고 가정하지 않는다.
- 검색 정확도와 근거 확인을 응답 속도보다 우선한다.
- 검색 DB에 기록을 저장하고 동일 조건의 결과를 재사용한다.
- PDF·TXT·HTML·DOCX 파일 가져오기를 포함한다. 가져온 자료도 같은 검색에서 사용하며 출처를 구분한다.
- GraphDB 확장을 고려해 문헌·문단·관계를 고유 ID와 근거로 연결한다.
- 로컬 모델을 우선 사용한다. 외부 모델 API와 원문 전송은 별도 승인 후 사용한다.
- 로컬 OCR을 1차에 포함해 스캔 PDF를 검색할 수 있어야 한다.
- 1차는 검색·원문/한국어 번역·검색 기록을 완성한다. 여러 문헌을 종합하는 AI 답변은 로컬 LLM을 사용하는 2차 기능이다.

## 앱 구성 제안

- 개인 PC의 브라우저 UI와 로컬 API 서버. 서버는 기본적으로 localhost에서 실행한다.
- Python 수집·추출·검색 서비스와 SQLite 원본 DB + FTS5 검색 기준선.
- 문헌 수집은 검색 요청과 분리한 재개 가능한 백그라운드 작업.
- 한국어·외국어 키워드 검색과 다국어 의미 검색을 조합하고 상위 결과 재정렬을 비교 평가.
- 로컬 임베딩·번역·재정렬 모델은 장비와 평가 데이터로 결정한다. 초기 모델 다운로드에는 네트워크가 필요할 수 있다.
- 번역은 원문 버전·문단·모델 버전에 연결하고 재사용한다. 번역 실패 시 원문과 상태를 보여준다.
- 원본 파일은 로컬 보관소에 저장하고 DB에는 해시·상대 경로·문헌 연결을 저장한다.
- UI 프레임워크, 벡터 색인 방식, 모델 이름은 샘플 검증 이후 고정한다.

SQLite FTS5는 본문 검색과 BM25 정렬을 지원한다. 한국어 짧은 질의·조사·외국어 동의어는 별도 평가하며 기본 토크나이저만으로 충분하다고 가정하지 않는다.
공식 기술 참고. https://www.sqlite.org/fts5.html

## 사용자 흐름

1. 자료실에서 수집 상태를 확인하거나 파일을 가져온다.
2. 한국어 질문과 출처·기간·문헌 종류·언어 조건을 입력한다.
3. 결과에서 일치 문단·문헌명·출처·발표일·관련도를 확인한다.
4. 상세 화면에서 외국어 원문과 대응하는 한국어 번역을 함께 읽는다.
5. 공식 원문 또는 로컬 보관 파일의 해당 페이지로 이동한다.
6. 검색 기록에서 당시 결과를 열거나 최신 자료로 다시 검색한다.

여러 문헌을 종합하는 생성형 답변은 2차에서 제공한다. 1차에서도 로컬 번역·임베딩·재정렬 모델을 사용할 수 있으며, 종합 답변 기능과 구분한다.

## 출시 범위

1차 출시는 두 사이트와 가져온 파일 검색, 로컬 OCR, 원문/한국어 번역 병렬 확인, 근거 위치 이동, 검색 기록·결과 재사용을 완료한 상태다. 공의회 자료는 제2차 이전을 포함해 조사한 목록별 확보·미확보 상태를 공개한다.

2차는 1차 검증을 통과한 뒤 로컬 LLM으로 여러 문헌을 검색하고 근거를 묶어 답변한다. 각 설명을 문헌 버전·근거 문단과 연결하고 상충하는 근거와 근거 부족을 표시한다. 답변 재사용에는 질의뿐 아니라 근거 집합·원문 버전·모델·프롬프트 버전을 반영한다. 모델 출력은 원문·번역과 구분해 보존한다.

## 수집과 문서 가져오기

- 공식 목록의 페이지 이동을 끝까지 조사해 발견 URL 목록을 먼저 저장한다.
- 문헌별 성공·실패·보류 상태를 저장하고 실제 수집 범위를 표시한다.
- 원문 버전의 해시로 변경을 감지한다. 동일 파일 재가져오기는 중복 저장하지 않되 유입 경로는 보존한다.
- 사이트 문헌과 사용자 파일은 URL·제목·날짜가 일치해도 자동으로 같은 문헌으로 확정하지 않는다. 대응 후보를 제시하고 확인 후 연결한다.
- 나주 본문의 메뉴·댓글과 교황청 문헌의 각주를 구분한다. 공식 문단 번호와 내부 검색용 분할 번호를 분리한다.
- PDF는 페이지, DOCX·HTML·TXT는 문단 위치를 기록한다. 텍스트 추출이 부족한 페이지는 로컬 OCR로 처리한다. 텍스트와 스캔이 섞인 PDF도 페이지별 처리해 기존 텍스트를 중복 색인하지 않는다.
- OCR은 페이지·언어·엔진/모델 버전·추출 위치·검토 상태를 기록한다. 원본 파일은 보존하며 판독이 불확실하거나 실패한 페이지를 표시한다. 사용자가 원본 페이지와 대조하고 교정한 텍스트는 새 추출 버전으로 보존한다.
- 깨진 파일, 추출 실패, 비어 있는 본문은 성공으로 색인하지 않는다.
- 로컬 수집 범위에서 문서 읽기·검색 기록 열기가 가능하도록 한다. 신규 수집과 공식 사이트 방문은 온라인 기능이다.

## 검색과 기록

- 질의 원문과 검색용 정규화 질의를 함께 보존한다. 한국어 동의어·용어 번역은 적용 내역을 기록한다.
- 제목·정확 구절·문단 번호로 찾는 검색과 주제·의미 검색을 구분한다.
- 두 출처와 가져온 파일 결과를 함께 볼 수 있고 각각 필터할 수 있다.
- 원문에 있는 인용문만 근거로 표시한다. 모델 번역과 설명에는 생성 표시를 붙인다.
- 캐시 키는 질의·필터·색인 버전·검색 모델 및 파이프라인 버전을 포함한다.
- 색인 갱신 후 새 검색은 갱신된 자료를 쓴다. 과거 기록은 당시 버전으로 열 수 있다.
- 재사용 시 새 기록은 기존 검색 실행을 참조하고, 재사용 사실과 최초 검색 시각을 표시한다.
- 검색 결과 없음과 검색·모델·수집 실패를 구분한다.

## 정확도와 성능 기준

- 실제 연구 질문 50개 이상을 확보하고 사람이 정답 근거를 검토한 평가 세트를 만든다.
- 나주·교황청·파일 검색, 한국어·외국어, 정확 구절·주제 질문을 포함한다.
- Recall@20과 nDCG@10, 정답 문헌 상위 노출률을 기준선과 비교한다. 통과 수치는 평가 자료를 만든 뒤 확정한다.
- 인용 위치·원문 버전·공식 링크·번역 대응 문단이 정확한지 검증한다.
- 한국어·외국어 스캔 PDF와 혼합 PDF 샘플로 OCR 인식·검색 성공·원본 페이지 연결·중복 방지를 검증한다. 엔진별 신뢰도 점수를 동일 척도로 비교하지 않는다.
- 지연 목표 초안은 캐시 p95 200ms, 키워드 p95 1초, 의미 검색·재정렬 p95 3초다. 모델 초기 로딩, 첫 번역, 네트워크 수집 시간은 따로 측정한다.
- 실제 PC RAM/GPU·문헌 수·검색 조건을 기록하고 속도 목표를 조정한다. 현재 확인한 PC는 RAM 약 32GiB, RTX 3060 12GB이며 전체 자료 규모 성능은 미검증이다.
- 캐시 무효화, 중단 재개, 문헌 변경, 중복 파일, 데이터 복원도 통과 기준에 포함한다.

## 공개 사이트 조사 근거

4단계의 로컬 결합 검색·문단 번역·버전별 캐시와 작은 비교 평가를 구현했다. [검증 보고](local-model-verification.md)에 초기 결과와 번역 실패를 기록했다. 5단계는 사용자 확인을 받은 A 연구실형으로 실제 자료실·검색·원문/번역·기록을 연결했다. [UI 검증 보고](ui-verification.md)에 범위와 한계를 기록한다. 전체 수집과 번역 품질·대규모 평가·운영 검증은 계속 남아 있다.

### 5단계 A 연구실형 구현

2026-10-31 사용자가 A 연구실형을 선택했다. 3안 시안은 `prototype/ui-layout-review`의 `c5efb3a`에 보존하며 main에 합치지 않는다. 이슈 #8의 결정을 따라 #9에서 실제 화면을 구현한다.

1. 표준 라이브러리의 루프백 전용 HTTP 서버에서 기존 Library·검색·번역 함수를 호출한다. 연결별 DB와 Host/Origin·본문 크기·파일 경계를 검증한다.
2. 왼쪽 메뉴·검색 조건·가운데 결과·오른쪽 원문/미검토 번역을 실제 자료에 연결한다. 자료실 가져오기, 문헌 버전, 검색 기록의 당시 열기/현재 재검색과 보관 파일 다운로드를 포함한다.
3. 합성 보관소의 API 경계/오류 테스트, 실제 보관소 검색과 브라우저 흐름, 기존 회귀 테스트로 검증한다. 문헌/페이지 전체 수집과 번역 품질 출시 판정·2차 AI 답변은 완료로 간주하지 않는다.

새 프레임워크 없이 Python 표준 서버와 HTML/CSS/JavaScript를 사용한다. 서버는 개인 PC 루프백 전용이며 공용 배포용 서버가 아니다. 번역은 명시적인 버튼으로만 생성하고 저장 번역은 모델 없이 열 수 있게 한다. 원본 HTML은 실행하지 않고 보관 파일은 다운로드로 제공한다.
